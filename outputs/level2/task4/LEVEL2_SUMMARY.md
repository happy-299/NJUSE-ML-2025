## 🛠 Level 2 方法与实现

### 1. 提示工程策略

#### 结构化提示模板
```
Task: Fix the code based on the review comment.
Language: {language}
Review: {comment}
Original Code: {old_code}

Instructions:
- Generate ONLY the fixed code
- Do NOT generate review comments or explanations
- Keep the same programming language and style
- Apply the suggested changes from the review

Fixed Code:
```

#### 改进要素
- **明确任务指示**: 明确要求生成代码而非评论
- **语言上下文**: 提供编程语言信息
- **输出格式规范**: 指定输出格式要求
- **否定指令**: 明确说明不要生成什么

### 2. 生成参数优化

| do_sample | False | True | 启用采样机制 |
| repetition_penalty | - | 1.2 | 避免重复生成 |

### 3. 后处理机制

Level 2实现了智能后处理:

## 🔍 结果分析

### 模型行为观察

从预测示例分析可见，即使使用Level 2的高级技术，模型仍然表现出以下特征:

1. **持续生成评论格式**: 仍倾向于输出`<msg>Please remove...`格式
2. **忽略明确指令**: 尽管提示明确要求生成代码，模型仍生成评论
3. **任务理解偏差**: 将代码修复任务理解为代码审查任务

### 技术局限性分析

#### 1. 预训练偏差
- CodeReviewer模型在预训练时主要学习生成评审意见
- 模型权重强烈偏向评论生成模式
- 仅靠提示工程难以完全克服这种偏差

#### 2. 指令遵循能力
- 模型对复杂指令的理解和执行能力有限
- 否定指令("不要生成评论")的效果不佳
- 需要更强的指令调优或微调

#### 3. 输出格式控制
- 模型难以准确控制输出格式
- 后处理虽有改善但效果有限
- 需要更精细的解码策略
