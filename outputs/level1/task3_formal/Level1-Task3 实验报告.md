# Level1-Task3 实验报告



## 1. 问题介绍

评审意见生成是代码评审自动化中的核心任务之一。其目标是根据提交的代码变更，自动生成自然语言形式的评审意见，以辅助代码审查者发现潜在问题、优化代码质量 。



- **输入**：代码变更数据，通常以 Diff Hunk 形式呈现，包含增加行、删除行及上下文。
- **输出**：针对该变更的评审意见序列 。



## 2. 数据预处理

1. **Diff 格式标准化**：
   - 将代码 Diff 中的 `+`（新增行）标记替换为特殊 Token `[ADD]`。
   - 将 `-`（删除行）标记替换为 `[DEL]`。
   - 未变更的上下文行标记为 `[KEEP]`。
2. **序列截断与填充**：
   - **Max Source Length**: 300。代码变更序列超过 300 Token 的部分被截断，不足部分使用 `[PAD]` 填充。
   - **Max Target Length**: 128。评审意见超过 128 Token 的部分被截断。
3. **数据采样策略**：
   - 受限于本地实验环境（无 GPU，仅 CPU），本实验采用了随机采样策略以缩短实验周期。
   - **训练集**：从原始训练集（约 11.8 万条）中随机抽取 **3,000 条** 样本。
   - **测试集**：原始测试集。



## 3. 论文复现

### 3.1 模型选择

- **模型架构**：**CodeT5-base** 。CodeT5 在大量代码语料上进行了预训练，具备优秀的代码理解与生成能力 4。
- **参数量**：约 220M。



### 3.2 训练参数配置

为适应本地 CPU 环境，对训练超参数进行了如下调整：

- **Batch Size**: 2
- **Learning Rate**: 3e-4
- **Epochs**: 1 (针对 3k 数据集，训练约 1500 步)
- **Optimization**: AdamW 优化器，配合线性 Warmup 策略。



### 3.3 推理设置

- **Beam Size**: **1** (Greedy Search)。

  *说明*：为了在有限时间内完成推理，本实验将 Beam Size 从论文推荐的 5 调整为 1。这显著提升了推理速度（约 5 倍），但可能牺牲了一定的生成多样性。

  

## 4. 结果与分析

| **指标 (Metric)** | **本实验结果 (Ours)** | **论文基线 (CodeT5-base)** |
| ----------------- | --------------------- | -------------------------- |
| **BLEU-4**        | **0.00**              | 4.83                       |
| **ROUGE-L**       | **1.41**              | -                          |
| **BERTScore F1**  | **81.11**             | -                          |



### 4.1 结果分析

1. **BLEU-4 (0.00)**：
   - BLEU-4 分数极低符合预期。BLEU 衡量的是 4-gram 的精确匹配。由于本实验仅使用了 **2.5%** 的训练数据且仅训练了 **1 个 Epoch**，模型尚未能学会生成与参考答案完全一致的长短语。此外，代码评审意见通常具有极高的多样性，即使语义相近，用词不同也会导致 BLEU 为 0。
2. **BERTScore (81.11)**：
   - BERTScore 较高，说明模型生成的文本在 **语义层面** 与参考答案保持了一定的相似性。这表明代码跑通且模型已具备基本的自然语言生成能力，而非生成乱码。
3. **复现限制因素**：
   - **数据量差异**：论文使用了全量数据（118k）训练，而本实验仅用了 3k。
   - **搜索策略**：Greedy Search (Beam=1) 倾向于生成高频、通用的短句，不如 Beam Search 生成的质量高。



## 5. 结论

本实验成功在资源受限的本地 CPU 环境中复现了 CodeReviewer 的评审意见生成任务。虽然受限于算力和时间，模型性能（BLEU）未达到 SOTA 水平，但完整跑通了从数据预处理、模型微调、推理生成到多维度评估（BLEU/ROUGE/BERTScore）的全流程，验证了实验代码的正确性和 CodeT5 模型在代码评审场景下的适用性。
